Many cloud phone tasks fail because of small surprises.

A notification permission popup appears. An app update prompt blocks the screen. The network retry button shows up. An account security notice interrupts the flow.

Each issue is easy by itself. Across many devices, it becomes exhausting.

## The user problem

Scripts usually follow fixed steps.

If a popup appears on top of the page, the button the script wanted to tap may be hidden. The script may click the wrong place or stop completely.

Common popups include:

- Notification permission.
- Gallery permission.
- Location permission.
- App update prompts.
- Login expiration reminders.
- Network error messages.

## A real scene

Imagine a team using cloud phones to upload media in batches.

The task is simple: open the app, choose media, fill text, and submit.

But on some cloud phones, the app shows a gallery permission popup the first time it opens. If the script does not handle that popup, the upload flow cannot continue.

## A better way to think about it

The answer is not always "wait a few more seconds."

A better process is:

- Detect whether the current screen is abnormal.
- Decide whether the issue is common and safe.
- If it is safe, run the matching recovery action.
- If it is not safe, record the reason and send it to a human.

## The difficult part

Not all popups mean the same thing.

Some can be closed. Some require permission. Some indicate account risk and should not be skipped.

The system needs more than script execution. It needs judgment around task state.
